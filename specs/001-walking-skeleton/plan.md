> **DO NOT IMPLEMENT YET.** This document is the technical plan only. No product code, config files, or scaffolding are created by this step. All file contents below are *proposed* and live only inside this plan until the implement step.

## Summary

Stand up a pnpm + Turborepo monorepo whose only runtime artifact is a Next.js 15 (App Router, TS strict, Tailwind v4) web app rendering the single line `Bristle — walking skeleton`. Wire repo-wide `typecheck`/`lint`/`build`/`dev` tasks through Turborepo, gate every branch and PR with a GitHub Actions workflow (install → typecheck → lint), and ship `apps/web` to Vercel as a PR preview and, on merge to `main`, to production. `apps/pipeline` is a README-only placeholder; `packages/ui|db|shared` are empty-but-compiling stubs. Proves the full delivery path before any feature exists.

## Technical Context

**Scale/Scope**: 1 deployable app, 1 placeholder app, 3 empty packages, ~20 config/source files total.

## Order of operations (dependency-ordered; implement step will follow this)

1. **Root toolchain skeleton first** — `.nvmrc`, `.editorconfig`, `.gitignore`, root `package.json` (with `packageManager`), `pnpm-workspace.yaml`. *Everything else depends on workspaces resolving.*
2. **Shared TS base** — `tsconfig.base.json`. Needed before any workspace tsconfig can extend it.
3. **Empty packages** — `packages/ui|db|shared` (`package.json`, `tsconfig.json`, `src/index.ts`). Simplest workspaces; validate that workspace resolution + typecheck work in isolation.
4. **Root ESLint flat config** — `eslint.config.mjs` (ignores `apps/web`). Depends on packages existing to lint.
5. **Web app** — `apps/web` (`package.json`, `tsconfig.json`, `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `src/app/{layout,page}.tsx`, `globals.css`). Depends on base tsconfig.
6. **Turborepo orchestration** — `turbo.json` + root scripts wire `build/dev/lint/typecheck` across workspaces. Depends on all workspace-level scripts existing.
7. **Pipeline placeholder** — `apps/pipeline/README.md`. Independent; excluded from toolchain.
8. **Install + lockfile** — `pnpm install` to generate `pnpm-lock.yaml` (committed). Validate SC-001.
9. **Local verification** — `pnpm typecheck`, `pnpm lint`, `pnpm --filter web dev` → confirm `localhost:3000` (SC-002/003/004).
10. **CI workflow** — `.github/workflows/ci.yml`. Depends on root scripts being green locally.
11. **Vercel config** — `vercel.json`. (Dashboard link already completed by user as a prerequisite; the post-push Vercel step is now verification-only.)
12. **Branch push + PR** — triggers CI (SC-005) + Vercel preview (SC-006a).
13. **Gitignore audit** — `git ls-files | grep -E "(node_modules|\.next|\.turbo)"` returns nothing (SC-007).
14. **Merge → production** — verify production URL within 90s (SC-006b, manual gate).

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | Tailwind v4 setup mismatch (v4 uses `@tailwindcss/postcss` + CSS `@import`, not v3's `tailwind.config.js` + directives) | Med | Med | Plan uses the v4 PostCSS plugin + `@import "tailwindcss"` only; no `tailwind.config.js`; no `@tailwind` directives. No tokens this slice limits blast radius. |
| R2 | ESLint 9 flat config vs `eslint-config-next` interop | Med | Med | `apps/web` uses `next lint` with `FlatCompat` bridge (Next's documented path); root uses native `typescript-eslint` flat config and *ignores* `apps/web` to avoid double-config conflicts. |
| R3 | `pnpm install` emits non-peer warnings, failing SC-001 | Low | Low | SC-001 permits peer warnings; any other category gets a written justification appended to spec. Frozen lockfile in CI/Vercel keeps installs deterministic. |
| R4 | Vercel can't locate the Next app in the monorepo | Med | High | Repo-root `vercel.json` with explicit `buildCommand` (`turbo --filter=web`) + `outputDirectory: apps/web/.next` + `framework: nextjs`; documented dashboard Root Directory = repo root. |
| R5 | `turbo-ignore` skips a build it shouldn't (false negative) | Low | Med | First deploy has no prior SHA so it builds; `turbo-ignore web` keys off the `web` workspace + its (currently empty) dep graph. Acceptable while `web` is the only real workspace; revisited in 1.3. |
| R6 | Node version drift (local Node 25 vs target 20) surfaces an incompatibility | Low | Med | `.nvmrc` = 20; CI uses `node-version-file: .nvmrc`; Vercel runtime pinned to Node 20. CI is the source of truth, not local. |
| R7 | `apps/pipeline` accidentally pulled into pnpm/Turbo/typecheck | Low | Low | Workspace globs list only `apps/web` + `packages/*`; pipeline has no `package.json`, so Turbo/pnpm never see it. |
| R8 | Generated dirs committed (`.next`, `.turbo`, `node_modules`) | Low | Med | `.gitignore` written in step 1, before any install/build; SC-007 audit in step 13 catches regressions. |

| R10 | Next 15 + React 19 peer/type mismatches with `@types/react` 19 | Low | Med | Pin React 19.1.0 + `@types/react` 19.x together; `skipLibCheck: true` in base tsconfig blunts third-party d.ts noise. |
| R11 | `verbatimModuleSyntax`/`isolatedModules` too strict for Next | Low | Low | Both are Next 15-compatible; `next.config.ts` and React 19 support them. If a conflict appears, relax in `apps/web/tsconfig.json` override only, with a comment (per §5). |
