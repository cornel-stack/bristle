## Overview

This slice ships the Tier 2 build-plan slice **2.4 — Blog index + post + first article**. Two new surfaces land: a Blog index at `/blog` and a dynamic blog-post route at `/blog/[slug]`. Both routes are statically prerendered (○ Static — no DB reads, no `force-dynamic`); the dynamic route uses `generateStaticParams` to emit all 7 article slugs at build time. The index reads top-to-bottom as an editorial table-of-contents: top nav + BlogHero (eyebrow `BRISTLE BLOG` + serif headline `Field Notes` + subhead) + BlogFilterChips (5 chips — All, Data analysis, Product strategy, Indie hacker, Devtools — client-side single-select filter state) + BlogFeaturedCard (the top featured article with the `IN THIS ISSUE` callout box quoting the article's pull-quote) + BlogArticleGrid (3-column grid of 6 secondary cards on desktop, stacks on mobile, conditionally rendered against the filter selection) + site footer. The blog-post route reads as a long-form research-journal entry: top nav + two-column body (left = `BlogPostHero` + `BlogPostBody`; right = sticky `BlogRailToc` + `TryBristleCard`) + site footer. One article — slug `what-50000-github-issues-reveal-about-developer-pain` — is the featured article with `featured: true` and `stubBody: false`; its body renders 4 numbered sections (Scope refusals, Comment count, Willingness-to-pay, Method & data) including an inline pull quote and an inline placeholder SVG figure. The other six articles share the same `BlogPostLayout` template but with `stubBody: true`, which collapses `BlogPostBody` to a single lead paragraph + a `Full article forthcoming.` caption — same `TryBristleCard` still renders in the rail. The central data store at `apps/web/src/components/blog/blog-articles.ts` exports all 7 articles as a typed `BlogArticle[]`; a `// [PLACEHOLDER — article content awaiting founder review before production launch]` header marks the discipline (same lighter pattern as slice-009 FR-013). `BlogRailToc` is the **third** structural mirror of the same `IntersectionObserver` + topmost-visible + mobile-pill-auto-scroll + reduced-motion-on-each-invocation pattern (slice-006 `FaqScrollSpyRail`, slice-009 `TocRail`, now slice-010 `BlogRailToc`); the tracked follow-up to dedupe into a shared `SectionScrollSpyRail` grows to absorb all three. **No edits to slice-005 / 006 / 008 / 009 files. No new top-level dependencies. No DB schema change.**

### Edge Cases

- **Deep-link to a section on the featured article** (`/blog/what-...#method-data`): the browser performs its native anchor-jump scroll on page load; the BlogRailToc's IntersectionObserver fires the moment the section enters the viewport and marks it active. The active state matches the URL hash within ~100ms of load.
- **BlogRailToc "between sections"**: when the visitor is scrolled to a position where no section's marker element is intersecting (e.g. between section 2's body bottom and section 3's heading), the rail keeps its previous `active` value — no flicker, no "no-section" intermediate state. Same rule as slice-006 FAQ rail and slice-009 TocRail.
- **BlogRailToc on stub-body articles**: a secondary article has `stubBody: true` and no `sections` content to derive TOC items from. The BlogRailToc receives an empty `items` array and renders nothing (returns `null`) — the right column collapses to just the TryBristleCard. This keeps the layout coherent (still a two-column body) without rendering a useless empty rail. Documented in clarification (b)'s extension and reaffirmed in AC US3-3.
- **Filter chip "no matches"**: not reachable in the shipped article set — every chip has at least one matching article (data-analysis = 2, product-strategy = 2, indie-hacker = 2, devtools = 1, all = 7). If the article set ever shrinks to a state where a chip has zero matches, the grid renders a single muted `<p>` line — `No articles in this category yet.` — in §6 voice. This is a defensive render path, not a tested-this-slice scenario.
- **Mobile pill row at narrow widths (320)**: the horizontal pill row scrolls horizontally inside its own container; the active pill auto-scrolls into view (`scrollIntoView({inline: "center", block: "nearest"})`) so the visitor always sees which section they're in. Instant under reduced-motion. Same pattern as slice-009 TocRail.
- **Reduced-motion at runtime**: the `prefers-reduced-motion` media query is read on each `scrollIntoView` invocation (not cached at component mount), so a user toggling the OS preference mid-session takes effect immediately on the next jump. Same pattern as slice-006 FAQ rail and slice-009 TocRail.
- **Visitor reads to the bottom of the featured article**: the last section (`method-data`) becomes the active section and stays active as the visitor scrolls past it (no section follows; the rail does not unset).
- **Unknown article slug** (`/blog/this-does-not-exist`): the dynamic route's `params.slug` lookup against the central data store misses; the route handler calls Next.js's `notFound()` which renders the standard 404 page. No custom 404 authored this slice — Tier 7 polish ships a Bristle-voiced 404.
- **`generateStaticParams` excludes a slug**: any article whose slug is not in the array returned by `generateStaticParams` will fall through to dynamic rendering on first hit. To stay `○ Static` for all 7 routes, `generateStaticParams` MUST return all 7 slugs derived from the central data store (verifiable by AC US3-4).
- **OG image strategy**: all 7 article routes and the `/blog` index reuse the slice-005 raster at `${SITE_URL}/og-image.png`. Per-article OG image generation (e.g. via `@vercel/og` dynamic image routes showing article title + author) is deferred to a future slice. This means the social-share preview is the brand wordmark + tagline for every article — acceptable for v0.2.0 launch (per clarification (d)).
- **Browser without IntersectionObserver** (none in target support — Safari 12.1+ baseline since 2019): the BlogRailToc still renders as static anchor links; the active-state tracking degrades silently to "no active state" — anchors still work (native browser anchor navigation), just no rail-side highlight. No JavaScript error. Same posture as slice-006 / slice-009.
- **JS disabled entirely**: the filter chips render as inert pill elements; the `All` set (all 7 cards) is what the visitor sees because no client-side filter logic runs. The cards still link to `/blog/{slug}` via standard `<a href>` so navigation works without JS. Acceptable degradation — the editorial surface remains readable, just not filter-able.
- **Modifier-key clicks on filter chips**: chips are `<button>` elements (they manipulate filter state, not navigation), so modifier-key behavior doesn't apply. Modifier-key clicks on the BlogArticleCard `<a>` links pass through to the browser's native behavior (open in new tab / window / etc.), same as the BlogRailToc anchors per AC US2-7.
- **Inline figure rendering**: the InlineFigure on the featured article's section 1 renders a hand-rolled inline SVG line-chart placeholder (~200px tall, full width). NO `recharts` / `chart.js` / other chart library is imported; the SVG is decorative and represents what the real chart will look like. The caption describes what the real chart will show. The founder swaps to a real chart in a future content patch before publishing.
- **Founder byline across all 7 articles**: every article uses `authorName: "Cornel Okoth"` and `authorInitials: "CO"` — overriding the design's `Elena Hwang` / `Jules Marin` placeholder bylines (per clarification (f)). Slice 008 already established Cornel as the founder name on the About page, and cross-page byline consistency matters more than honoring the design's placeholder names.
- **`/signup` CTA in TryBristleCard**: still a known out-of-scope 404 until Tier 3 auth ships (slice 3.1). The CTA renders as a real `<a href="/signup">` link; clicking it lands on a 404 today and flips to live the moment Tier 3 ships. Documented carry-forward, same posture as the slice-005 nav `Login` / `Start free` CTAs.

## Requirements *(mandatory)*

### Functional Requirements

**Routes (US1, US2, US3, US4)**

- **FR-001**: The slice-005 soft-404 stub at `apps/web/src/app/blog/page.tsx` (`<ComingSoon version="0.2.4" />`) MUST be replaced wholesale with the full Blog index. The new file is an async Server Component that imports the central `BLOG_ARTICLES` array and renders the page's section composition (BlogHero, BlogFilterChips + BlogFeaturedCard + BlogArticleGrid composed via the client-state owner, site footer reused).
- **FR-002**: A new dynamic route MUST be created at `apps/web/src/app/blog/[slug]/page.tsx`. It is an async Server Component that:
  1. Exports `async function generateStaticParams()` returning `{ slug }` for every article in `BLOG_ARTICLES` (all 7 slugs).
  2. Looks up the article for the request's `params.slug`; if not found, calls Next.js's `notFound()`.
